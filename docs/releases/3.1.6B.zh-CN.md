# Validation Assistant 3.1.6B 发布说明

3.1.6B 汇总了 3.1.6A 之后的停止与恢复、上下文压缩、推理强度与 Priority 模式，以及 Thread 关联数据清理改进。

## 停止与运行恢复

- “停止”现在会真正中断当前模型请求、工具执行和本次运行所启动的子进程，不再只改变前端状态。
- Windows 使用受控的进程树终止，仅清理 VA 当前运行创建的 Python、PowerShell 等子进程，不影响其他独立程序。
- 运行取消后的连接与客户端状态会被独立释放，避免连续快速停止后新 Thread 出现连接错误。
- Subagent 继续保留 Thread 级状态；恢复后可等待尚未完成的任务，完成、取消和重启中断均返回明确状态。

## 上下文压缩

- 压缩边界由整轮对话改为模型协议事务：Assistant 的工具调用和对应 Tool 结果始终作为不可拆分单元。
- 支持增量 checkpoint；新一轮压缩会合并旧摘要，只替换已经覆盖的历史，保留最近的实时上下文。
- 扩大结构化摘要和工具证据容量，并保留更早与更近期的重要用户需求，减少长 Thread 中的信息遗失。
- 当存在尚未闭合的工具调用时会明确延后压缩，避免生成非法消息顺序。

## 模型、推理强度与 Priority 模式

- 输入区新增紧凑的模型与推理强度面板，可直接选择支持的模型及 `none`、`low`、`medium`、`high`、`xhigh`、`max`。
- 仅对能力目录确认支持的模型开放相应推理档位；不支持时显示 Locked，避免发送无效参数。
- 支持 Priority/Fast service tier 的模型可点击闪电开启加速；未确认支持的模型不会错误开放。
- Max 档位保留独立配色；Priority 开启后使用实心闪电和流动星光效果，并兼顾较低的长期渲染开销。

## Thread 数据清理

- 删除对话时，同时删除 `app/data/tool_results` 中父 Thread 和所有关联 Subagent 的长工具结果。
- 删除 Project 下的全部对话时执行同样的关联清理。
- 清理按明确的 `:subagent:` 边界匹配，不会误删 ID 前缀相似的其他 Thread。

## 验证

- 前端 JavaScript 语法检查通过。
- 完整测试通过：`969 passed, 1 skipped`；跳过项为当前平台不适用的 Windows 检查。
- 保留 1 条既有的 Starlette TestClient 弃用警告，不影响运行或发布。
