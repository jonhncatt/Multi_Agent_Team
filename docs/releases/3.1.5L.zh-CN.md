# Vintage Programmer 3.1.5L 发布说明

3.1.5L 是一次安全边界和企业推广导向的发布，重点是把网络能力集中到 Full Dev/Full Access，并为风险命令和网络来源代码增加可审计的一次性审批。

## 重点更新

- Full Access 风险命令审批：`git pull/fetch/clone/submodule`、`npm install/add/update/exec`、`python -c`、`node -e` 等不再在 Full Access 下直接硬拦截，而是先经过 allowlist，再弹出 Approve once。`curl/wget/npx/pip install` 默认不在 allowlist，只有管理员显式加入后才会走审批。
- Tainted 文件执行保护：`web_download` 下载文件和从 tainted archive 解压出的文件会记录来源 URL、domain、SHA-256、大小、content type、session/run 等；执行前要求单次审批，且命令、cwd、session/project、risk details、文件 hash 必须匹配。
- 默认离线边界：Chat/Default 与 Code/Auto 继续保持离线安全边界；Full Access 才允许网络工具和风险命令审批。
- 审批 UI：命令审批弹窗展示 exact command、cwd、风险原因、来源 URL/hash，并明确说明批准后会在 host 环境实际执行，不是沙箱。批准或取消后弹窗会立即关闭。
- Auto 模式保持：前端手动选择 Auto 后，不再被 health/env 默认值在下一轮覆盖。
- Agent spec 同级化：`vintage_programmer` 中文 spec 迁到 `agents/vintage_programmer/locales/zh-CN/`，与 `en`、`ja-JP` 同级；根目录只作为旧 workspace fallback。
- 新闻/网页质量修复：`web_fetch` 默认抓取预算恢复到 120000，上限 500000，避免“今日新闻”等请求只拿到站点简介。

## 安全说明

- 这是产品级 guard，不是 OS sandbox。用户批准后，命令会在 host 环境实际执行。
- Allowlist 决定命令是否有资格进入审批；审批不是 allowlist 的替代品。
- Taint 检测是 best-effort provenance check，不能替代容器或 VM 隔离。
