# Vintage Programmer 3.1.5Y 发布说明

3.1.5Y 汇总了 3.1.5X 之后的任务管理、Runtime 可观察性、上下文压缩、审批连续性和取消恢复改造。这个版本继续收敛 Harness 的职责：权限、审批、取消和技术协议由 Runtime 保证；工具失败后的策略选择交还模型；工作区改动则始终按真实保留状态向用户报告。

## Task 与 Project Profile

- 首页新增持久化 Task 工作流，可把当前 Thread 总结成可跨 Thread 继续的任务。
- Task 按业务项目保存和筛选；切换项目后仍能查看、加载对应任务，不会错误跳回 Vintage Programmer 项目。
- 支持更新和删除 Task；内置 `update-task` Skill 在写入前展示新内容并要求用户确认。
- 项目添加完成后可选择绑定 Project Profile；跳过后也可通过项目右键菜单绑定、更换或解除。
- Project Profile 采用 `project_profiles/builtin` 与 `project_profiles/team` 两层结构，只有显式绑定的 `AGENTS.md` 会进入当前项目上下文。

## Runtime、Plan 与审批

- 原 Run 页面收敛为 Runtime：展示当前 Turn 状态、Plan、工具事务、审批、耗时、失败和结束后的可追溯记录。
- 审批时明确显示“等待用户审批”，审批卡片提高视觉权重；提交同意或拒绝后立即收起，避免重复点击。
- 审批暂停会保存原始工具调用、审批请求和当前 `plan_state`；恢复后继续同一个逻辑 Turn，Plan 和总耗时不重新起算。
- 新增 Thread 级 `Always Allow` 命令规则；一次批准后，同一 Thread 内匹配规则的命令不再反复询问。
- 修复后台命令仍在运行时重复请求审批的问题，批准后的运行命令会复用原执行状态。
- Windows 默认命令列表加入 `where`，并保持命令、工作目录和权限边界校验。

## 模型主导的工具续行

- 取消“一个 Turn 累计 5 次工具失败就停止”的规则。
- 不再因为重复错误指纹、重复工具、工具调用次数、运行时长或 Runtime 推测的“没有进展”而强制停止。
- 实际失败和策略拒绝会作为结构化观察返回模型，由模型决定换参数、换工具、解释阻塞或结束任务。
- `where` 与 `rg` 的退出码 `1` 被识别为正常的“未找到”，不再计入工具失败。
- `failed`、`rejected` 与 `skipped` 保持分离；未实际执行的跳过调用不会污染失败统计。
- 审批、用户取消、上下文硬边界、Provider 错误和工具协议错误仍由 Runtime 管理。

## 上下文窗口与 Compact

- 区分模型最大窗口和实际运行窗口：GPT-5.6 可显示约 1.05M 模型上限，同时默认采用 272K 运行预算。
- 轮前与轮中统一使用 `ContextWindowStatus`，避免 UI 数字、压缩判断和实际请求预算不一致。
- 历史保留由固定 Turn 数改为 token budget，并保证 assistant/tool/result 事务不会被截成不完整协议。
- 删除按 8 次工具调用或 120K 历史噪音直接触发全文压缩的旧逻辑。
- 单个工具结果默认只向模型提供最多 10K token；只有真实发生截断时才保存完整结果，并可通过 `read_tool_result` 分段续读，无需重跑工具。
- Provider 降级到更小窗口模型时，会在下一次请求前重新计算并执行本地确定性压缩。
- Context 状态能正确区分尚未整理、已自动整理和手动整理，避免已经 Compact 后仍显示“未整理”。

## 追加消息、Skills 与 Thread 标题

- 普通 Enter 在 Agent 运行期间把消息排入下一 Turn；Shift+Enter 作为 steer，在安全模型边界注入当前 Turn。
- 修复连续发送两条任务时的等待顺序、重复用户消息、错位 AI 回复和 Runtime 状态错配。
- 保持 queued/steered Turn 的 System Prompt 与执行过程可检查，不再出现首条执行过程缺少 System Prompt。
- Skill 清单不再因展示长度省略末尾 Skill；Redmine 读取后仍可发现并调用工作总结等后续 Skill。
- 工具详情保留实际 Skill 名称；脱敏聚焦 `.env` 中的敏感键，不再无差别隐藏普通名称和参数。
- 新 Thread 自动生成简短标题，并修复刷新后本地化空标题问题。

## 取消、失败和保留的工作区改动

- 用户停止后，旧 Turn 会先进入权威 `interrupted` 终态并清理待审批、待输入和运行状态，然后同一 Thread 的新 Prompt 才能启动。
- 覆盖“刚开始生成、工具执行前、工具执行中、文件已修改后取消，以及立即重试”等取消时序。
- Turn 失败或取消不会擅自回滚工作区；Runtime 会列出已确认修改的文件、最后一次验证结果，并明确提示“更改仍然保留”。
- 对无法精确枚举修改文件的命令，页面提示检查 `git diff`，避免用户把失败误认为完全没有改动。
- 下一 Turn 会收到一次短提示，从当前工作区继续，不假设回滚，也不盲目重复上轮补丁。

## UI、Eval 与仓库整理

- 首页行动卡片从 5 个收敛为最近 3 个，减少执行区噪音。
- 新增可选橘黄色主题，并调整为更沉稳的爱马仕橙方向。
- 工具恢复 Eval 可直接从 Eval 页面查看和运行，确定性案例不调用真实 Provider。
- 新增 `search_codebase` 文件路径误作目录、`select-string` 被拒后改用 `rg`、查询未命中、五次不同失败、验证恢复、取消后立即重试和保留改动等回归案例。
- 清理过时缓存、旧架构草案和历史品牌资源，新增当前文档索引、Project Profile 和 Runtime 可靠性说明。

## 兼容性与验证

- 保持现有 Thread、旧 Session 迁移、API、前端调用和 OpenAI-compatible Chat Completions 接口兼容。
- 发布门禁已通过：Python 编译检查、前端 JavaScript 语法检查，以及全量测试 `786 passed`。
