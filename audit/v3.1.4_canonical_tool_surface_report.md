# v3.1.4 Canonical Tool Surface Cleanup Report

## Summary

This cleanup enforces one authoritative tool surface for Vintage Programmer.

- Only the canonical registered tools remain supported.
- Legacy tool names are no longer accepted as compatibility aliases.
- `LocalToolExecutor.tool_specs`, `packages/office_modules/tools.py`, `app/tool_metadata.py`, Workbench descriptors, docs, default eval JSON, and `LocalToolExecutor._execute_impl()` now point to the same canonical names.
- Legacy names remain only in negative non-exposure tests, retained internal helper method bodies, and this audit directory.

## Production Helper Cleanup

- `LocalToolExecutor.execute()` no longer accepts the removed legacy names.
- Canonical public tool methods now call canonical/private implementation helpers instead of legacy-named implementations.
- `normalize_tool_name()` no longer performs legacy alias mapping; it only trims and lowercases.
- Office helper logic and prompt text now reference only canonical tool names.
- Session listing internals were renamed away from legacy tool-name collisions (`list_recent_sessions`), so grep-based canonical checks no longer confuse internal methods with tool aliases.
